# Разработка

## Стек

| Область | Технология |
|---|---|
| Платформа | Expo SDK 57, React Native 0.86 (New Architecture), TypeScript |
| Анимации и жесты | react-native-reanimated 4, react-native-gesture-handler |
| Графика | react-native-svg |
| Хранение данных | expo-sqlite |
| Уведомления | expo-notifications (только локальные) |
| Интерфейс iOS 26 | expo-glass-effect (Liquid Glass), expo-blur как запасной вариант |
| Шрифт | Onest |

## Локальный запуск

```bash
npm install
npx tsc --noEmit      # проверка типов
npx expo start        # сервер разработки
```

Проект использует нативные модули, которых нет в Expo Go, поэтому для запуска на устройстве нужна development-сборка:

```bash
npx expo run:android  # требуется Android SDK
npx expo run:ios      # требуется macOS и Xcode
```

Папки `ios/` и `android/` генерируются командой `npx expo prebuild` и в репозиторий не добавляются. Нативные настройки задаются в `app.json` и плагинах из `plugins/`.

## Архитектура

### Данные

Задачи хранятся в SQLite (`src/lib/db.ts`):

| Таблица | Назначение |
|---|---|
| `tasks` | Задачи: дата, начало и длительность в минутах, категория, статус, напоминания |
| `series` | Правила повторения по дням недели |
| `kv` | Настройки и служебные значения |

### Состояние

`src/lib/store.ts` содержит глобальное состояние и все действия с задачами. Каждое изменение сразу сохраняется в базу и может быть отменено кнопкой «Отменить». Раз в 30 секунд и при возврате в приложение выполняется проверка:

- задачи, закончившиеся без отметки, получают статус «пропущено»;
- создаются экземпляры повторяющихся задач на текущую и следующую неделю.

### Уведомления

`src/lib/notifications.ts` пересобирает очередь уведомлений после каждого изменения задач или настроек. iOS хранит не более 64 запланированных уведомлений, поэтому в очередь попадают 60 ближайших. Очередь обновляется при каждом открытии приложения.

### Подпись iOS

`src/lib/signing.ts` читает дату `ExpirationDate` из файла `embedded.mobileprovision` внутри установленного приложения. По ней планируются напоминания о продлении подписи.

## Выпуск версии

1. Увеличьте `version` в `app.json`, а также `ios.buildNumber` и `android.versionCode`.
2. Добавьте запись в `CHANGELOG.md`.
3. Выполните push в `main` — GitHub Actions соберёт и опубликует релиз.
